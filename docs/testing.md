## Como rodar os E2E

`npm run build && npm run test:e2e` (o Playwright sobe `next start -p 3100`; com `E2E_BASE_URL` ele usa um servidor já ativo). Em ambientes com Chromium pré-instalado e sem acesso para baixar navegadores, aponte `PLAYWRIGHT_CHROMIUM_PATH=/caminho/para/chromium`.

Última execução registrada: 23/10/2026, na master f91a079 (contagens na linha de E2E da tabela acima). Primeira varredura (20/10/2026, build de produção local, projetos Pixel 7 + Desktop Chrome): **26/26 aprovados** — axe sem violações sérias/críticas em `/`, `/explore`, `/personalities`, `/login`, `/signup`, `/shop`, `/offline`; navegação por teclado com `aria-current`; troca de idioma; checkout e rotas protegidas redirecionam para login; sinalização de demonstração. Correções feitas a partir da varredura: contraste do token `fg-subtle` (3,3:1 → ≥4,6:1 nos dois temas) e nome acessível do logotipo contendo o texto visível (WCAG 2.5.3).

## Como o teste de RLS funciona

`scripts/db/test-rls.sh` recria `ultra_hero_test` (shim Supabase + migrations + seed) e executa `supabase/tests/rls_scenarios.sql` numa única transação (rollback no fim). Papéis são simulados exatamente como o PostgREST faz: `set role authenticated|anon` + `request.jwt.claims`. Funções `tests.ok` e `tests.expect_error` imprimem `PASS` ou abortam.

Para adicionar um cenário: copie um bloco `S<n>`, crie usuários em `auth.users` se precisar, e use `tests.login(uid, email)`.

## Contas de teste

Não há senhas no seed. Para testar portais no ambiente remoto: admin cria convites (`/admin/invitations`) ou provisiona contas demo (`/admin/settings`, exige service role no servidor). O primeiro login do e-mail de bootstrap recebe papel admin.

## O que ainda não é automatizado

- Fluxos autenticados usam as contas demo (um toque em `/login`); sem `DEMO_ACCOUNTS_PASSWORD` no ambiente eles pulam. O checkout completo ainda não tem jornada E2E. A operação dos fornecedores pelo admin e o portal `/seller` desligado têm checagens só de leitura em `tests/e2e/admin-seller-ops.spec.ts`; as regras de banco ficam no S62 (0053).
- Relógio real (Garmin, Oura, WHOOP, Polar): pronto e oculto (`WEARABLES_REAL_ENABLED` desligada na Vercel; `connect_open = 'false'` em `health.config`). O banco é coberto pelo RLS S43–S51 e, no remoto, com a chave desligada, `health_consent_grant` devolve `health_disabled` para conta não demo e `demo_account_cannot_connect` para conta demo (0 consentimentos gravados). A conexão de ponta a ponta com as marcas só pode ser exercitada depois de ligar (`docs/decisions/hoje-relogio.md`, seção "Roteiro de ligar").
- Comparação real OpenAI vs Gemini — `npm run eval:recommendations` roda os cenários com o motor determinístico e só compara provedores quando há chaves.
- Auditoria completa WCAG 2.2 AA — axe cobre uma parte; o restante está no `docs/launch-checklist.md` para verificação manual.
